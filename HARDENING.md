# ProRag — Hardening Report

My honest read on how production-ready each file is. **Lower % = look here first.**
The percentage is not "code quality" — it's *how much would survive contact with real
users, odd inputs, and failure*. A small tidy file can score low if it's papering over
something.

Sorted weakest-first inside each section. Updated 2026-08-03 (product-ization arc #1–#24 landed 2026-07-31 → 08-01).

## If you only look at five things

1. **`.env`** (30%) — a live API key in plaintext.
2. **`prorag/llm.py`** (55%) — no timeout, retry, or concurrency limit on any LLM call; one hung provider request hangs a chat.
3. **`web-next/components/pdf-viewer.tsx`** (65%) — `pdfCache` never evicts, so memory grows unbounded across a session.
4. **`prorag/admin/router.py`** (70%) — the largest new surface (597 lines) and the newest code; auto-admission + rule semantics + the private cross-module imports are where the next review should start.
5. **The no-frontend-login gap** — sessions come from `/auth/login` via curl/scripts; the admin dashboard UI (#25, the one open issue) doesn't exist yet. Until it lands, auth is real on the API and invisible in the browser.

## Cosmetic but user-visible

`answer-text.tsx` displays raw markdown/LaTeX as literal characters. On your AI-foundations PDF, answers routinely contain `\( O(1/\sqrt{N}) \)` and `**bold**`, which currently render as that exact syntax rather than formatted math. Not a robustness problem — but the most visible rough edge in the product right now.
